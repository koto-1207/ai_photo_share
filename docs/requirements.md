# 写真共有アプリ 要件定義

## 1. アプリの概要

友人同士で旅行や日常の写真を見せ合う、インスタグラム風の写真共有Webアプリ。

- 技術: Python / Flask / PeeWee（DBはSQLite）
- 写真1枚と短いキャプションを投稿し、新しい順に一覧で見る

## 2. 想定ユーザー

- 友人同士で旅行や日常の写真を共有したい人
- **閲覧者**: ログインしていなくても投稿一覧と投稿詳細を見られる
- **ログインユーザー**: 投稿や自分の投稿の管理ができる（追加機能を入れたら、いいねとコメントも）

## 3. 画面一覧と画面遷移

### 画面一覧


| 画面        | ログイン | 内容                 |
| --------- | ---- | ------------------ |
| 投稿一覧（トップ） | 不要   | 投稿を新しい順に表示する       |
| 投稿詳細      | 不要   | 1件の投稿を表示する         |
| ログイン      | 不要   | ユーザー名とパスワードでログインする |
| ユーザー登録    | 不要   | 新しいユーザーを登録する       |
| 投稿作成      | 必要   | 写真とキャプションを投稿する     |


### 画面遷移

- 投稿一覧 → 投稿詳細（投稿をクリック）
- ログイン → 投稿一覧（ログインに成功したとき）
- 投稿作成 → 投稿一覧（投稿に成功したとき）
- ユーザー登録 → 投稿一覧（登録に成功したとき。自動でログインする）
- 投稿詳細 → 投稿一覧（「一覧へ戻る」をクリック）
- 未ログインで投稿作成を開く → ログイン
- ログアウト → 投稿一覧

詳細は [screens.md](screens.md) を参照する。

## 4. 必須機能（この順番で実装する）

小さく分けた単位ごとに、動くことを確認してから次に進む。

### 4-1. ユーザー登録

- [ ] ユーザー名・メールアドレス・パスワードで登録できる
- [ ] ユーザー名は30文字まで
- [ ] ユーザー名かメールアドレスが重複していたらエラーを表示する
- [ ] パスワードはハッシュ化して保存する



### 4-2. ログイン / ログアウト

- [ ] ユーザー名とパスワードでログインできる
- [ ] 間違っていたらエラーを表示する
- [ ] ログアウトできる
- [ ] ヘッダーにログイン状態（ユーザー名、またはログインへのリンク）を表示する



### 4-3. 投稿作成

- [ ] ログインユーザーだけが投稿画面を開ける（未ログインならログイン画面へ）
- [ ] 写真1枚（jpg / png）とキャプションを投稿できる
- [ ] 写真なし、対応していない形式、サイズ超過（例: 5MB）はエラーにする
- [ ] キャプションは短め（例: 200文字まで）にする



### 4-4. 投稿一覧

- [ ] 誰でもトップページで投稿一覧を見られる
- [ ] 新しい順に並べる
- [ ] 写真、キャプション、投稿者名、投稿日時を表示する



### 4-5. 投稿詳細

- [ ] 誰でも投稿詳細を見られる
- [ ] 一覧の投稿をクリックすると詳細へ移動する
- [ ] 写真、キャプション、投稿者名、投稿日時を表示する



## 5. 余裕があれば追加する機能（上から優先）

1. **自分の投稿の削除**: 投稿者本人だけが削除できる。画像ファイルも削除する
2. **キャプション編集**: 投稿者本人だけが編集できる
3. **いいね**: 1人1投稿につき1回まで。取り消せる。件数を表示する
4. **コメント**: ログインユーザーが投稿にコメントできる。投稿詳細ページに表示する
5. **画像の縮小・サムネイル**: Pillowで縮小して、一覧の表示を軽くする
6. **アイコン画像**: 登録時やあとから設定でき、投稿の横に表示する

今回やらないこと: 検索、フォロー

## 6. 非機能要件

- **セキュリティ**: パスワードはハッシュ化する（`werkzeug.security`）。フォームはCSRF対策をする（Flask-WTF）。本人チェックはサーバー側で行う
- **アップロード**: 拡張子と画像の中身を確認する。ファイル名はサーバー側で作り直す（例: UUID）。`MAX_CONTENT_LENGTH` でサイズを制限する
- **規模**: 友人同士で使う小規模アプリを想定する。ローカル環境で動けばよい
- **使いやすさ**: スマホでも見られる簡単なレイアウトにする。エラーはflashメッセージで表示する



## 7. 実装時に注意すべきこと

- 機能は1つずつ作って、ブラウザで動作を確認してから次に進む
- `SECRET_KEY` はコードに直接書かず、環境変数などから読み込む
- アップロードした画像とDBファイルは `.gitignore` に入れる
- PeeWeeのモデルは最初に設計しておく（User / Post。追加機能で Like / Comment）。Like は (user, post) の組み合わせを重複できないようにする
- 一覧で投稿者名を表示するときは、JOINを使ってクエリの回数を増やしすぎない
- 削除や編集など状態を変える操作はPOSTで受け付ける（GETでは受け付けない）
- テンプレートは `base.html` を継承して、ヘッダーを共通化する

## 8. 入力ルール（バリデーション）

チェックはサーバー側（Flask-WTF のバリデータ）で必ず行う。HTMLの `required` や `maxlength` は補助として付けてよい。
前後の空白は取り除いてからチェックする（パスワードは除く）。

### ユーザー登録

| 項目 | 必須 | ルール | エラーメッセージの例 |
|---|---|---|---|
| ユーザー名 | ○ | 3〜30文字。半角英数字と `_`（アンダースコア）だけ使える。重複不可。大文字と小文字は区別しない（`Taro` と `taro` は同じとみなす） | 「ユーザー名は3〜30文字の半角英数字と _ で入力してください」「このユーザー名は使われています」 |
| メールアドレス | ○ | 255文字まで。メールアドレスの形式（`xxx@xxx.xx`）であること。重複不可。小文字にそろえて保存する | 「メールアドレスの形式が正しくありません」「このメールアドレスは登録済みです」 |
| パスワード | ○ | 8〜64文字。使える文字に制限は設けない | 「パスワードは8文字以上で入力してください」 |
| パスワード（確認） | ○ | パスワードと一致すること | 「パスワードが一致しません」 |

- 登録画面にはパスワード（確認）の入力欄を追加する
- メールアドレスは形式だけをチェックし、実際に届くかどうかの確認（確認メールの送信）はしない

### ログイン

| 項目 | 必須 | ルール |
|---|---|---|
| ユーザー名 | ○ | 空でないこと |
| パスワード | ○ | 空でないこと |

- 失敗したときは「ユーザー名またはパスワードが違います」とだけ表示する（どちらが違うかは伝えない。登録済みのユーザー名を知られないため）

### 投稿作成

| 項目 | 必須 | ルール | エラーメッセージの例 |
|---|---|---|---|
| 写真 | ○ | 拡張子が jpg / jpeg / png。Pillowで開ける画像であること。5MBまで | 「jpg または png の画像を選んでください」「ファイルサイズは5MBまでです」 |
| キャプション | | 200文字まで。空でもよい | 「キャプションは200文字までです」 |
